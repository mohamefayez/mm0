# نشر أسيل على GitHub والاستضافة

## الحالة

المشروع مجهز للرفع، لكنه لا يُعتبر مرفوعًا أو منشورًا بمجرد تجهيز الملفات. يلزم مستودع مخصص في حساب المالك، ثم استضافة تدعم Node.js 24 وقرصًا دائمًا لقاعدة البيانات. GitHub Pages لا يدعم الإدارة والطلبات الحالية.

## نسخة الرفع

شغّل `node scripts/prepare-release.mjs`. ينشئ مجلدًا جديدًا داخل `.local` يحتوي الكود والصور العامة والمستندات اللازمة، ويستبعد كلمات المرور والطلبات وقاعدة البيانات والنسخ الاحتياطية والملفات المحلية. لا ترفع مجلد المشروع كاملًا بالسحب والإفلات.

الصور المستخدمة موجودة داخل `public`، ولا تحتاج مجلدات الصور الأصلية لتشغيل النسخة. أمر `npm run store:setup` يحافظ على الصور الموجودة وتعديلات الإدارة ويضبط رقم واتساب المؤكد إذا كان فارغًا فقط.

## تشغيل Docker على الاستضافة

1. انسخ `.env.example` إلى `.env` واضبط رابط HTTPS النهائي في `NEXT_PUBLIC_SITE_URL` و`ASEL_PUBLIC_ORIGIN`.
2. شغّل `docker compose up -d --build`.
3. وصّل HTTPS reverse proxy إلى `127.0.0.1:3000`.
4. كلمة المرور الجديدة موجودة داخل الحاوية في `/app/.local/admin-access.txt`. اقرأها محليًا على الخادم عبر `docker compose exec store cat .local/admin-access.txt`، ثم غيّرها من الإدارة. لا تنشرها في المستودع أو المحادثات.
5. افتح `/ar/admin` وعدّل الأسعار والمخزون والأحجام وسياسات المتجر والشحن. التغييرات تحفظ في volume مستقل ولا تحتاج إعادة نشر.

لا تستخدم `docker compose down -v`؛ هذا يحذف وحدات تخزين البيانات. خذ نسخة احتياطية قبل تحديث الخادم عبر `docker compose exec store npm run store:backup`، وانسخ النسخ إلى مكان خاص خارج الخادم. جدولة النسخ اليومية تتم بعد تحديد الاستضافة.

ملفات Docker جاهزة، لكن تشغيلها يحتاج اختبارًا على جهاز عليه Docker؛ إذا لم يكن متاحًا محليًا، اتبع دليل Node في `DEPLOYMENT.md`.

## قبل تفعيل البيع

- الأسعار الحالية مؤقتة، ويظل الوضع تجريبيًا حتى مراجعتها.
- ٨ مسودات تحتاج تأكيد أسماء المنتجات، و١١ غلافًا قديمًا يحتاج تحسين الصور.
- لا توجد بيانات شحن أو سياسات نهائية معتمدة من المالك بعد.
- اختبر طلبًا على الدومين المنشور وتأكد من التحويل إلى رقم واتساب الصحيح قبل تفعيل البيع والفهرسة.
